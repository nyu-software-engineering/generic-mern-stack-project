## Existing interfaces and state

- [`MyListings({ initialFormOpen = false })`](../../front-end/src/pages/listings/MyListings.jsx) owns listing loading/retry, search/status, form, edit ID, preview ID, and mutation feedback. [`CreateListing()`](../../front-end/src/pages/listings/CreateListing.jsx) only opens this same form. Cancel resets and navigates to `/listings`. Save replaces/inserts the server response, clears the form, and opens preview without changing URL. Editing a published listing preserves its status. Drafts offer Preview; published items offer Pause; paused items offer Publish.
- The listing load effect has a `current` cleanup guard. A ref blocks duplicate save/status calls synchronously. Pending, loading, or load error disables management controls. Failed writes keep form values and known listings. Status success closes that item's preview. Search trims and matches title/category locally. Preserve these paths and guards. Source: [MyListings.jsx](../../front-end/src/pages/listings/MyListings.jsx).
- [`services/listings.js`](../../front-end/src/services/listings.js) uses GET `/listings/mine`, POST `/listings`, PUT `/listings/:id`, and PATCH `/listings/:id/status`. Successful writes hydrate shared cache. Full owner refresh replaces only that owner's records and removes vanished records. Cache functions clone values and compare string-equivalent IDs. Source: [mockDataService.js](../../front-end/src/services/mockDataService.js).
- [`OwnerDashboard()`](../../front-end/src/pages/ownerDashboard/OwnerDashboard.jsx) fetches on every search/status change and retry. Its cleanup guard ignores obsolete responses. Rows hide during loading/error; the previous summary remains visible. [`getOwnerDashboard({ search, status })`](../../front-end/src/services/ownerDashboard.js) encodes query values. The [route](../../back-end/routes/ownerDashboard.js) filters owner rows by title, borrower name/ID, and stored status. Summary always covers all owned rentals. Active includes `extension_requested`; income counts completed rentals with server rounding. Do not recompute totals from filtered rows or add owner overdue filtering.
- [`RentalActivity`](../../front-end/src/pages/renterDashboard/RenterDashboard.jsx) independently loads/retries rentals with a cleanup guard. Its status filter is local and uses [`displayStatus`](../../front-end/src/services/bookings.js), including derived overdue for active/extension rentals past return. It retains the existing date formatter and booking links. [`getMyRentals()`](../../front-end/src/services/renterDashboard.js) merges fetched rentals into cache for booking readers.
- [`SavedItemsProvider`](../../front-end/src/context/SavedItemsProvider.jsx) independently loads saves, guards obsolete reads, and blocks writes per listing with a ref set. Success updates provider state. [`SaveListingButton` and `SavedItemsStatus`](../../front-end/src/components/SaveListingButton.jsx) already use shared styles and expose pending, failure, retry, and known saved state. Keep the [provider route boundaries](../../front-end/src/App.jsx), including the outer mock-data gate.

## Validation and UX gaps

The form requires title, category, description, price, and terms. Price uses native `min=0`, `step=0.01`, plus a finite nonnegative check. Trimmed blank title/description/terms currently return silently. The [server validator](../../back-end/routes/ownerListings.js) also checks category membership, trims text, accepts free listings, and owns identity/status metadata. The [API helper](../../front-end/src/services/api.js) preserves `ApiError(message, status, errors)` and its timeout.

Silent rejection is an existing usability bug. The parent confirmed it in the browser: spaces-only title, description, and terms with valid category/price leave the form open with zero alerts after Save and preview. Nearby errors, field associations, and invalid state are #144 acceptance work under the approved feedback requirements. Keep validation rules unchanged. New constraints or workflows need separate scope. Other source-level gaps are search fields without visible labels, plain empty/error messages, old blue controls, and layouts without long-content protection. These remain source observations. Owner empty results do not distinguish no activity from no matches. Sources: [MyListings](../../front-end/src/pages/listings/MyListings.jsx), [OwnerDashboard](../../front-end/src/pages/ownerDashboard/OwnerDashboard.jsx), [legacy CSS](../../front-end/src/index.css).
