# Discovery implementation research for #142

Source inspection on November 18, 2026 at `f13aaad`. Scope is the approved [Direction A design](../design/2026-11-18-nyu-redesign-design.md). This report proposes implementation and verification. It does not claim browser checks passed.

## Reuse and contracts

- **Shell and account:** `Navbar` already uses `Link`, `NavLink`, account context, and sign out followed by `/`. Its brand opens `/browse` when signed in and `/` otherwise. `AuthProvider` stores account state in React memory. It exposes `currentUser`, `signIn(email, displayName)`, `verifyEmail()`, `updateProfile(displayName, campusArea)`, and `signOut()`. Keep this account behavior separate from service identity, which remains `CURRENT_USER_ID`. Sources: [Navbar](../../front-end/src/components/Navbar.jsx), [AuthProvider](../../front-end/src/context/AuthProvider.jsx), [booking identity](../../front-end/src/services/bookings.js).
- **Wrappers:** `AuthProvider` wraps the app. `Navbar` sits outside routes. Pathless `MockData` waits for shared bootstrap data and offers retry. Pathless `SavedItemsProvider` wraps only Browse, Item Details, and renter dashboard. It renders children while saves load. Keep these boundaries and all existing paths. Sources: [main](../../front-end/src/main.jsx), [routes](../../front-end/src/App.jsx), [bootstrap wrapper](../../front-end/src/components/MockData.jsx), [saved provider](../../front-end/src/context/SavedItemsProvider.jsx).
- **Browse:** controlled search and category start as `''` and `'All'`. Trim search before requesting. Convert `'All'` to `''`. Reset clears both controls. `ListingResults({search, category, onClear})` remounts per filter combination. Nonempty search waits 200ms. Cleanup prevents stale rendering and stale cache writes. Preserve loading, retryable error, polite result count, populated grid, and empty/reset states. Sources: [Browse](../../front-end/src/pages/browse/Browse.jsx), [categories](../../shared/options.mjs).
- **Public listings:** `searchListings({search='', category='', signal}={})` returns a listing array from `GET /listings`, encoding filters with `URLSearchParams`. It caches returned records unless the signal was aborted. The signal does not reach fetch. `getPublicListing(id)` returns one record from `GET /listings/:id`. It rejects noncanonical positive integer IDs, including `02`, `mine`, and `1e2`, with `ApiError` status 404. Sources: [public service](../../front-end/src/services/publicListings.js), [transport](../../front-end/src/services/api.js).
- **Cards:** `ListingCard({listing})` consumes `id`, `title`, `category`, `description`, numeric `price`, and `ownerId`. It links to `/browse/:id`, formats price to two decimals, and hides Save for owned items. `listingImage()` always returns the existing placeholder. Do not invent image or verification data. Sources: [card](../../front-end/src/components/ListingCard.jsx), [image helper](../../front-end/src/services/bookings.js).
- **Saved state:** `SaveListingButton({listing, compact=false})` and `SavedItemsStatus` already provide accessible names, pressed/busy state, loading, retry, and mutation errors. Provider state is `savedListings|null`, `loadError`, `pendingIds`, `retry()`, and `setListingSaved(id, boolean)`. Per-ID protection prevents duplicate writes. Update known state only after success. GET/POST/DELETE use `/saved-items`, with `{listingId}` for writes. Sources: [save controls](../../front-end/src/components/SaveListingButton.jsx), [provider](../../front-end/src/context/SavedItemsProvider.jsx), [save service](../../front-end/src/services/savedItems.js).
- **Details and booking:** keyed details requests ignore stale results and cache successful records. Preserve loading, 404 unavailable, other error/retry, and owner-name fallback. Owned items omit save, request form, and report. Date fields remain required. Pickup cannot precede local today. Return must follow pickup. Positive day counts show the existing estimate. Valid submission navigates to `/listings/:id/request?start=YYYY-MM-DD&end=YYYY-MM-DD`. Booking reads these parameters and sends `{listingId,startDate,endDate,message}` through its existing API service. Preserve formatter helpers, cache hydration, and local-only booking handling. Sources: [details](../../front-end/src/pages/browse/ItemDetails.jsx), [booking entry](../../front-end/src/pages/booking/Booking.jsx), [booking API](../../front-end/src/services/bookingsApi.js).
