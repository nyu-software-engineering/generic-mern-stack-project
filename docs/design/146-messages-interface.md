# #146 interface design

Follow the [approved NYU direction](2026-11-18-nyu-redesign-design.md) and [research contracts](../research/146-messages-implementation.md). Keep routes, callbacks, helpers, enums, validations, local state, and network boundaries. No APIs, schemas, rental fields, or storage migrations.

Use `.ds-page.ds-messages` as the journey scope. Reading pages cap content at 720px; board uses 1184px. Use shared gutters, violet actions, white surfaces, Helvetica stack, 16px body, 14px metadata, 28/32px headings, and 44px controls. Reuse `.ds-heading`, `.ds-button` variants, `.ds-field`, `.ds-feedback`, `.ds-status`, `.ds-text-link` from [design-system.css](../../front-end/src/styles/design-system.css).

Put shared layout rules in `styles/messages.css` under `.ds-messages`. Keep chat-specific rules in chat CSS. Add journey classes instead of editing global legacy card/form selectors. Scope the native dialog itself because top-layer presentation needs explicit ownership. Retain Quick Borrow's module for unique layout. Use wrapping, `min-width:0`, stacked phone actions/dates/replies, and readable full terms. Board filters become a named button group with `aria-pressed`. Keep one global bottom navigation and its existing safe-area allowance.

OfferForm keeps its four props and numeric `{totalPrice,startDate,endDate}` submit payload. Replace overlay with native `<dialog>` opened by `.showModal()`. Label it with its heading. Focus total price on entry. Native modal focus containment must hold for Tab and Shift+Tab. Escape/cancel, explicit Cancel, and a true backdrop click call `onCancel` once. Ignore clicks inside the panel. Capture the opener and restore focus after closure/unmount when it remains connected. Limit height and scroll within the dialog.

Use stable prefixed field IDs and matching `htmlFor`. Link field errors through `aria-describedby`; set `aria-invalid`. Focus the first invalid field after submission. Apply this to offer/create/respond forms. Preserve Quick Borrow native required checks and alert/status feedback. Catch storage-write failure at submit, retain values, and show recovery text without changing the service. Keep labels, helper text, error text, and focus visible. Remove unsupported verification copy. Say Quick Borrow was saved in this browser. Preserve its inbox destination without implying direct recipient messaging.
