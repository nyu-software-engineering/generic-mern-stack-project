## Team Norms

### 1. Meeting Schedule
- **Monday:** Standup immediately after class.
- **Wednesday:** Standup immediately after class.
- **Friday:** Meeting time must be agreed upon and confirmed by Wednesday evening.
- Meetings should start on time. Standups must stay within 15 minutes; other meetings should generally stay within 30 minutes.
- Avoid last-minute scheduling and weekend meetings unless all members agree.
- Any additional meetings should have a clear agenda and be scheduled in advance.

### 2. Task Assignment & Deadlines
- Assign tasks at the beginning of each sprint.
- Every task must have a clear owner, deliverables, and deadline recorded in GitHub Issues.
- Aim to finish assigned tasks at least 24 hours before the official deadline.
- Members are responsible for tracking and updating their own progress.

### 3. Communication
- Discord is our primary communication channel.
- Important decisions, deadlines, and task assignments must be documented in Discord or GitHub.
- Prefer asynchronous communication for questions that do not require a meeting.
- Members should review existing documentation before asking questions already addressed there.

### 4. Definition of Done
A task is considered complete when:
- Its acceptance criteria are satisfied.
- Relevant functionality has been tested.
- Required documentation is updated.
- Code changes have been reviewed and merged through a Pull Request.

### 5. Accountability
- Members must communicate blockers promptly during standups.
- Members unable to attend a scheduled meeting should notify the team in advance.
- Repeated absences or missed commitments should first be addressed directly within the team.
- If unresolved after two standups, concerns should be escalated to the TA or professor.

### 6. Development Standards
- Use feature branches and descriptive commit messages.
- Follow consistent coding conventions.
- All code must be reviewed and tested before merging.
- Keep the main branch functional and avoid unnecessary complexity.

### 7. Pull Request & Branch Management
- The last person working on a branch should notify and @mention the team in Discord when the PR is ready for review and merging.
- Avoid duplicate or premature notifications.
- Keep active branches until their PRs are merged, then delete the merged branches to keep the repository organized.
