# Mockaroo setup

The shared mock API returns users, listings, and rentals. Its saved configuration is recorded here so it can be recreated without access to the original account.

## Run the app

Use the setup commands in the [root README](../README.md#development-setup). Copy `front-end/.env.example` to `front-end/.env.local`, then set `MOCKAROO_API_KEY` using the key shared privately. Restart Vite after changing it.

- Remote endpoint: `GET https://my.api.mockaroo.com/dormshare.json`
- App request: `GET /mock-api/dormshare.json`
- Authentication: Vite adds the `X-API-Key` header from the environment file.
- Response: an object with `users`, `listings`, and `rentals` arrays.
- Initial records are cached by Mockaroo for one day. Local app edits stay in memory and reset on reload.

Teammates using the existing endpoint only need the key. They do not need a Mockaroo account. Editing its saved schema requires access to the account that owns it.

## Recreate or update the saved API

1. In Mockaroo, create a schema named `DormShare`.
2. Add one field named `data`, with type **Formula** and blank percentage **0**. Paste the contents of [schema-formula.rb](./schema-formula.rb) into it.
3. Set the row count to **1**, the format to **JSON**, and enable **array** and **include null values**. Save the schema.
4. Create a mock API with method **GET** and route **/dormshare.json**. Paste [api-handler.rb](./api-handler.rb) into the handler and save it.
5. When changing the schema or handler, clear the API's cached results before checking the response.
6. If recreating it under another account, use that account's key in `.env.local`.

The formula currently generates 8 users, 8 listings, and 14 rentals covering all seven rental statuses. User IDs are strings (`owner-1`, `student-2` through `student-8`). Listing and rental IDs are numbers. Listing 5 belongs to `student-2`; the other listings belong to `owner-1`. Names and prices are generated by Mockaroo. Dates are relative to the day of generation.

These Ruby files configure Mockaroo. The app fetches the generated response and does not import these files as fixtures. When editing the saved configuration, update these copies in the same PR.
